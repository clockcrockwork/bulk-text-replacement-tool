# 一括置換ツール

複数のテキストを、**グループごとの置換ルール表**で一括変換するブラウザツールです。
同じ原稿から「A用」「B用」といった別バージョンを一度に作ることを想定しています。

処理はすべてブラウザ内で完結します。**入力したテキストとルールは外部へ送信されません**
（状態はブラウザの localStorage にだけ保存されます）。ふだん外部へ出る通信は Google Fonts からの
フォント配信だけです。

例外は、自分で「GitHubから追加」を使ったときだけです（下の「GitHub から追加」参照）。
そのときも、リポジトリの内容はブラウザが GitHub（api.github.com）から直接受け取り、
このサイトのサーバーを経由しません。サーバーが受け持つのはログインのトークン交換だけです。

この約束は二重に固定しています。

- **CSP**: `connect-src 'self' https://api.github.com` で、それ以外の宛先への fetch / XHR / sendBeacon / WebSocket をブラウザ側で塞いでいます（変換を走らせる Web Worker にはページの CSP が引き継がれないので、Worker の中では通信の API そのものを最初に塞いでいます）
- **E2E**: 原稿とルールに目印を仕込み、どのリクエストの URL・ヘッダ・本文にも現れないことを検証しています。GitHub を使わない流れでは GitHub にもサーバーにも一切つながないこと、GitHub から取り込んだ本文がサーバーへ送られないことも見ています（`e2e/privacy.spec.ts`）

## できること

- **入力**: `.md` / `.txt` / `.tex` のドラッグ＆ドロップ、複数ファイル同時、全画面エディタでの編集、GitHub のリポジトリからの読み取り専用の取り込み
- **ルール**: 置換元 × グループの表。正規表現（`$1` などの後方参照つき）、大小区別、適用順（同時／順次）を行ごとに指定
- **表の入出力**: Markdown 表・CSV・TSV からのルール読み込みと、CSV / TSV への書き出し
- **出力**: グループごとの結果を置換箇所ハイライト付きで確認、個別コピー／保存、全ファイルの ZIP 保存
- ライト／ダークテーマ、キーボードだけでのルール表編集

### 「同時」と「順次」

| 適用順 | 動き |
| --- | --- |
| **同時** | 連続する「同時」行をまとめて1回で適用する。そのパスの開始時点のテキストを一度だけ走査し、**長い一致を優先**する（同着ならルールの定義順）。置換で生まれた文字列は同じパス内では再走査しないので、ルールが**連鎖しない**。 |
| **順次** | その行だけを単独のパスとして、**それまでの置換結果の全体に対して**適用する。前のパスの置換結果と周囲の文字列にまたがる一致も拾う。 |

例: `a → b`, `b → c` の2行に `a` を入力すると、両方「同時」なら `b`、2行目が「順次」なら `c` になります。

### サンプル

初回はサンプルの原稿とルールが入っています。**原稿を取り込むかテキスト欄を追加すると
自動で片付き**、サンプルが変換結果に混ざったり、サンプルのルールが実原稿に当たったり
しません（片付けた直後は「元に戻す」で戻せます）。

サンプルに手を入れたあとは、それはあなたの作業なので自動では消しません。入力タブの
「サンプルを片付ける」で消してください。

### 同じ名前のファイルを入れ直したとき

外部のエディタで直した原稿を入れ直すと、**置き換える / 別の入力として追加 / キャンセル**
を選べます。黙って2件に増やしたりはしません。

### 取り込める大きさ

ブラウザの中だけで動くので、大きすぎる原稿を読み込むとタブが長く止まったり落ちたりします。
そのため、ファイルの取り込みには上限があります（ローカルのファイル・GitHub・「表から読み込み」のファイルで同じです）。

- **1ファイル 5MiB（5,242,880 バイト）まで**。超えるファイルは読み込まずに外し、名前を知らせます
- **1回の取り込みの合計も 5MiB まで**。複数選択や GitHub の一括取り込みで合計が超えたら、
  1件も取り込みません。一度に選ぶファイルを減らしてください
- 取り込むとブラウザの保存容量を超えそうなときは、取り込む前に確かめます。取り込んだら
  作業データを書き出して手元に残してください
- 作業データの読み込みと、エディタでの手入力・貼り付けには、この上限は掛かりません

日本語の長編小説 1 冊（30 万字）は約 0.9MB です。上限と根拠は
[docs/resource-policy.md](docs/resource-policy.md) にあります。

### GitHub から追加

入力タブの「GitHubから追加」で、GitHub のリポジトリにある `.md` / `.txt` / `.tex` を
取り込めます。ファイル名を押して1件ずつ確かめながら取り込むほか、チェックボックスで
複数のファイルやフォルダをまとめて選べます。

- **読み取り専用**です。コミット・push・Pull Request・自動同期は行いません
- GitHub での許可はリポジトリ単位です。どのリポジトリを読ませるかは GitHub の画面で選びます
- ブランチを選んだ時点の**コミットに固定**して辿ります。開いている間にブランチが進んでも
  勝手に追従せず、「最新に更新」を押したときだけ新しいコミットへ移ります
- 取り込んだ入力には、どのリポジトリ・ブランチ・パス（とコミット）から来たかが残ります。
  同じファイルをもう一度取り込むと **更新 / 別の入力として追加 / キャンセル** を選べます。
  ファイル名が同じでも、別のパスのファイルは別の入力として扱います
- 接続の資格情報は保存しません。再読み込みやタブを閉じたあとは、もう一度接続します。
  「このタブの接続を解除」が捨てるのもこのタブの接続だけで、GitHub App に与えたアクセス権は
  GitHub の設定から変更します。GitHub 自体へのログインも切れないので、共用の端末では必要に応じて
  GitHub からもログアウトしてください
- 取り込んだ本文は、手で追加した原稿と同じくブラウザの中（と作業データの書き出し）に入ります
- フォルダにチェックを入れると、まだ開いていない配下も含めて対象になります。ファイルの本文を
  取得する前に、見つかったファイルの一覧・件数・合計サイズを確認できます（件数が多いとき、
  大きさの分からないファイルがあるときは警告し、合計が 5MiB を超えるときは取得できません）。確認の前に、ファイルの一覧を数えるための
  GitHub API は使います
- GitHub API の利用上限に達したときは、このページを開いている間、解除の目安の時刻まで GitHub へは一切要求しません（「再試行」も「確認」「取得」も押せません）。再読み込みや接続し直しのあとは、最初の1回の応答で待ちを知り直します
- 空の入力が1つだけ残っているときは、通常のファイルの取り込みと同じく、取り込んだファイルで置き換えます
- ブラウザへの保存に失敗している間は、1件の取り込みも一括の確定もできません（ダイアログの中から作業データを書き出せます）
- まとめて取り込むときは、全件の取得と確認が終わってから一度に反映します。1件でも失敗したら
  入力は何も変わりません。確認の途中でダイアログを閉じても、取得した内容と選んだ取り込み方法は
  残り、開き直せば続けられます（捨てるのは「選択へ戻る」だけです）
- 確定の前に、追加する件数と本文を置き換える件数を表示します。GitHub 側が前回の取り込みから
  変わっていないファイルは、まとめて更新する対象から外します（更新すると手元の修正が失われるだけのため）
- フォルダを選んだときは、対応する形式（.md / .txt / .tex）のファイルだけを取り込みます。
  選んだ範囲にある対象外のファイルの件数は、取得の前の確認画面に出ます
- 一括取り込みは追加と更新だけで、同期ではありません。GitHub で削除・移動したファイルの入力は
  自動では消えません
- 一括取り込みの途中の内容はこのタブの中にだけあり、再読み込みやタブを閉じると取得し直しになります。
  ブラウザへの保存に失敗している間は、一括の取得と確定はできません
- 一括で取り込んだあとも「元に戻す」で取り込む前に戻せます。確認画面も選んだ内容ごと戻るので、
  取り直しにはなりません
- 初回のサンプルは取り込むと自動で片付きます。「元に戻す」でサンプルも戻ります

設定の手順は [docs/github-app-setup.md](docs/github-app-setup.md)、仕様は
[docs/github-import-v2.md](docs/github-import-v2.md) にあります。

### 複数行のルール

置換元・置換先には**改行をそのまま含められます**。ただしルール表は「たくさんのルールを
横断して見る一覧」なので、セル自体は1行のままにしています。

- 改行を含むセルは `一行目… [複数行]` と要約表示になります
- そのセルを押すか、**Shift+Enter** で複数行のエディタが開きます。狭い画面のカード表示では、
  各欄の右にある編集ボタンからも開けます（キーボードが無くても複数行にできます）
- CSV / TSV に書き出しても改行は保たれ、読み戻せます（Markdown 表は複数行セルの
  受け渡しには使えません）
- 置換先に `\n` と書いても改行にはなりません。文字どおりの `\n` として扱います
  （正規表現モードの**置換元**では `\n` が改行を指します）

### 置換先を空にしたとき

置換先が空の行は「削除」ではなく「そのグループでは何もしない」になります。
グループごとに「この語は変えない」を表現するための仕様です。

ただし**正規表現モードなら削除できます**。展開後に空文字になる置換先を書けば、
一致した範囲は取り除かれます（例: 置換元 `(不要な)?文字` ・置換先 `$1` で、
グループが無いときに空になる）。リテラルの置換では削除できません。

### 縦書き用の記法を含む原稿

置換元・置換先は**ただの文字列**として扱います。ルビ記法（`|漢字《かんじ》`）のような
記法も、そのまま書けばそのまま一致します。

ひとつだけ注意が要るのは**取り込む表の書式**です。Markdown 表は `|` を列の区切りとして
使うので、`|` を含むルールを Markdown 表で受け渡すとそこで列が割れます。取り込み側は
`\|` のエスケープを1文字の `|` として読みますが、他のツールが書き出した表はそうとは
限りません。`|` を含むルールを扱うなら **CSV か TSV を使ってください**（このツールの
書き出しもその2つです）。

CSV / TSV はどちらも、区切り・改行・引用符を含むセルをクォートして書き出し、読み込み側も
クォートを解釈します。**このツールが書き出したものは、そのまま読み戻せば値が変わりません。**
（他のツールへ渡すときは、TSV のクォートを解釈しない実装もあるので CSV が無難です）

取り込む表の列数が見出し行と食い違うときは、確定する前に知らせます。足りないセルは空として
扱われるので、区切りが壊れていても「読み込めた」ように見えてしまうためです。

## 出力ファイル名

入力の「ファイル名」は**出力ファイル名の指定**です。中身の形式は変換しません（`.md` と
書いても Markdown へ組み直したりはせず、常に UTF-8 のプレーンテキストです）。

| 入力したタイトル | 出力名 |
| --- | --- |
| `第一章` | `第一章.txt` |
| `第一章.md` | `第一章.md` |
| `story.part1.md` | `story.part1.md` |
| `title.html` | `title.html.txt` |
| `第一章/序` | `第一章_序.txt` |
| （空欄） | `text-1.txt` |

- 保証している拡張子は `.txt` / `.md` / `.tex` で、取り込みで受け付ける形式と同じです。
  それ以外は消さずに `.txt` を足します（`.html` のまま出すと、開いたときにブラウザが
  HTML として解釈し得るため。名前は残したいので削りません）。
- `/` は階層ではなく名前の一部として `_` にします。ZIP の中だけ階層になり、個別保存では
  末尾しか使われない、という食い違いを避けるためです。

## 作業データのバックアップ

原稿・グループ・ルールはブラウザの中（localStorage）にだけ保存されます。サーバーには
置かないぶん、**ブラウザ側の都合で消えることがあります**。

- Safari は、サイトへの訪問が7日途切れるとスクリプトが書いた保存領域を消します
- ブラウザの「サイトデータを削除」「履歴を消去」
- プライベートウィンドウを閉じたとき
- 保存領域がいっぱいになったとき（数MB程度で頭打ちになります）

そのため、ヘッダーの**「作業データ」から JSON に書き出して手元に置いてください**。同じ画面から
読み込みもできます。読み込みは「ファイルを選ぶ → 中身を確かめる → 置き換えを確定する」の
3段階で、確定するまで今のデータには触りません。

保存に失敗したときは画面下に警告を出し続けます（消えるトーストにはしていません）。
出ている間の編集は保存されないので、書き出してください。

書き出しの形式は版 2 です（GitHub から取り込んだ入力の出自を含むため）。版 1 の
ファイルもそのまま読み込めます。凍結した V1（ロリポップ版）は版 2 を読み込みません
（出自だけを黙って落として読み込むより、拒否される方が安全なため）。

## 文字コード

- 取り込むファイルは UTF-8 として読み、不正なら **Shift_JIS(Windows-31J)** として読み直します。古い原稿や Excel が書き出した CSV をそのまま渡せます。先頭に BOM のある UTF-16（Excel の「Unicode テキスト」など）は、BOM に従って読みます。
- 取り込んだファイルが UTF-8 として読めず Shift_JIS とみなした場合は、その旨を画面で知らせます。**推測でしかない**ので、文字化けが無いか目で確かめてください。書き出しは常に UTF-8 です。
- 正規表現は**常に `u` フラグ付き**で解釈します。`𠮷` のような補助漢字を分断せず、`\p{Script=Han}` も使えます。代わりに `[a-\d]` や裸の `{` のような、`u` が無ければ通る書き方はエラーになります（書き方によって `.` が1文字にも2文字にもなる状態を作らないため）。
- **文字数は表示しません。** 取り込める大きさはファイルのバイト数（5MiB）で決めているので、文字数を数えても判断材料になりません（サロゲートペアや異体字セレクタをどう数えるかで値が変わるだけです）。上限の内側で最後まで置換されることは自動テストで担保しています。
- **一致はコードポイント列の完全一致で、Unicode 正規化はしません。** 見た目が同じでも
  合成済みの「が」(U+304C) と「か」+濁点 (U+304B U+3099) は別の文字列として扱われ、片方を
  書いたルールはもう片方に当たりません。macOS から持ってきたファイル名や、入力環境の違う
  原稿を混ぜたときに起きます。当たらないときは、原稿とルールのどちらかを書き直して
  表記を揃えてください（正規化してしまうと、意図して使い分けている表記まで潰すため、
  ツール側では触りません）。

## 原稿には手を加えません

このツールが自動で整形するのは**出力ファイル名だけ**です。原稿・ルール・変換結果の
文字列そのものには、圧縮も正規化もしません。

次はすべて意味を持ち得るので、そのまま保ちます。

- 改行、行頭の全角空白・半角空白（字下げ）、連続する空白、タブ
- Markdown や Web 小説の記法、`<!-- -->` を含む本文
- 全角と半角の違い、Unicode のコードポイントの差

（アプリ自身の配信物 — HTML / CSS / JS — は軽くしています。それとこれは別のレイヤーです。）

## 対応ブラウザ

スマートフォンでの利用を前提にしており、**Safari も保証対象**です。
自動回帰は Chromium / WebKit（デスクトップ）と WebKit（iPhone エミュレーション）で回しています。
Playwright の WebKit は Safari そのものではないので、リリース前の最終確認は実機で行ってください。
特に**日本語 IME は自動テストで再現できません**（Playwright の入力は OS の IME を通りません）。
ルール表で変換候補を Enter で確定したときに、行移動や行追加が誤発火しないことは実機で見てください。

## V2: GitHub import

V2 では、GitHub repository から `.txt` / `.md` / `.tex` を **read-only** で取り込みます
（1ファイルずつの取り込みと、複数ファイル・フォルダの一括取り込み）。
GitHub への commit / push / PR 作成はこの段階では扱いません。

権限・認証・privacy 境界・tree picker・snapshot・上限・失敗時の扱いまで含む正本仕様は
[docs/github-import-v2.md](docs/github-import-v2.md) を参照してください。実装追跡は Issue #12 です。

## 開発

```bash
npm install
npm run dev        # 開発サーバー
npm run check      # lint + typecheck + test + build（コミット前にこれ）
npm run test:e2e   # ブラウザでの E2E テスト（初回は npx playwright install chromium webkit）
```

| コマンド | 内容 |
| --- | --- |
| `npm run dev` | Vite の開発サーバー |
| `npm run build` | 型チェック＋本番ビルド（`dist/`） |
| `npm run preview` | ビルド結果の確認 |
| `npm run lint` | Biome によるチェック（lint + フォーマット） |
| `npm run lint:fix` | Biome の自動修正 |
| `npm run typecheck` | `tsc --noEmit`（アプリ用と Node 側の2構成） |
| `npm run test` | Vitest（ロジックのユニットテスト） |
| `npm run coverage` | Vitest + カバレッジ（閾値つき） |
| `npm run test:e2e` | Playwright（実ブラウザでの E2E テスト） |
| `npm run check` | lint → typecheck → test → build をまとめて実行 |

Node のバージョンは `.nvmrc` と `engines` で 22 に固定しています。

## 構成

```
src/
├── lib/         ロジック（純粋関数・DOM非依存・テストあり）
│   ├── replace.ts    置換エンジン（同時／順次、ヒット数、ハイライト範囲）
│   ├── regex.ts      正規表現のコンパイルと $1 展開
│   ├── table.ts      Markdown 表 / CSV / TSV の入出力
│   ├── zip.ts        依存なしの ZIP 生成
│   ├── fileName.ts   ファイル名のサニタイズと重複解決
│   ├── gridNav.ts    ルール表のキーボード移動
│   ├── format.ts     画面とファイル名の書式
│   ├── text.ts       BOM の付け外し
│   ├── inputFiles.ts 取り込めるファイルの判定と読み込み
│   ├── browser.ts    ダウンロード・クリップボード（唯一の副作用）
│   └── storage.ts    localStorage（読み込み時に検証・正規化）
├── state/       useReducer による状態管理
├── hooks/       React フック
├── components/  UI（ErrorBoundary が復旧画面を持つ）
├── styles/      デザイントークンとコンポーネントCSS
└── types.ts     ドメイン型
e2e/             Playwright の E2E テスト（mobile/ は狭い画面専用）
design/          元になった Claude Design のエクスポート（参照用）
```

### テストの分担

| 層 | ツール | 見るもの |
| --- | --- | --- |
| `src/lib/`, `src/state/` | Vitest | 置換の意味論、表の入出力、ZIP のバイト列、保存データの正規化、reducer の遷移 |
| 画面全体 | Playwright | 変換の流れ、ファイル取り込み、モーダルのフォーカス、キーボード操作、永続化、ダウンロード、狭い画面のレイアウト |

コンポーネント単体のテストは置いていません。UI の振る舞いは E2E で、ロジックはユニットテストで見る、という分け方です。

## デプロイとリリース系統

完全な静的サイトなので、`dist/` をそのまま配信できるホスティングで動きます。
ただし、V1 以降は配信先ごとに役割を分けています。

| 系統 | ブランチ | 配信先 | 方針 |
| --- | --- | --- | --- |
| 本流 | `main` | Vercel production | 継続開発する唯一の本筋。GitHub 連携など V1 後の機能追加はここへ入れる |
| コンテスト提出版 | `release/lolipop-v1` | ロリポップ | V1 を固定した保守系統。新機能は入れず、提出・公開維持に必要な最小修正だけを backport する |

V1 の固定基点はタグ `v1.0.0`（V1 freeze prep PR #10 の squash merge）です。
`release/lolipop-v1` へ `main` を丸ごと merge / rebase して追従させません。
共通して必要な不具合修正は原則 `main` で直し、ロリポップ版にも必要なものだけを
小さい commit / PR 単位で選択的に backport します。ロリポップ固有のホスティング修正は
release 側だけで行って構いません。

ロリポップ版へ入れてよいのは、セキュリティ・プライバシー、データ消失／破損、
コンテスト要件、ホスティング互換性、起動不能など**公開維持に必要な修正**です。
GitHub 連携、新機能、UI の作り直し、理由のない依存更新は `main` にだけ入れます。

Vercel は `vercel.json` 済みで、`main` の production deployment を本番とします。
ロリポップへは `release/lolipop-v1` を checkout して build した `dist/` を使います。

本番ビルドでは sourcemap を配りません。HTML の開発者向けコメントも配信物から外し、
ユーザーの原稿・ルール・変換結果には minify / 正規化をしない、という境界を
`e2e/dist.spec.ts` で固定しています。

詳細は [RELEASE_POLICY.md](RELEASE_POLICY.md) を参照してください。
