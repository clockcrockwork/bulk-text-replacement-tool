# 一括置換ツール

複数のテキストを、**グループごとの置換ルール表**で一括変換するブラウザツールです。
同じ原稿から「A用」「B用」といった別バージョンを一度に作ることを想定しています。

処理はすべてブラウザ内で完結します。**入力したテキストとルールは外部へ送信されません**
（状態はブラウザの localStorage にだけ保存されます）。外部へ出る通信は Google Fonts からの
フォント配信だけです。

この約束は二重に固定しています。

- **CSP**: `connect-src 'none'` で fetch / XHR / sendBeacon / WebSocket をブラウザ側で塞いでいます
- **E2E**: 原稿とルールに目印を仕込み、どのリクエストの URL・ヘッダ・本文にも現れないことを検証しています（`e2e/privacy.spec.ts`）

## できること

- **入力**: `.md` / `.txt` / `.tex` のドラッグ＆ドロップ、複数ファイル同時、全画面エディタでの編集
- **ルール**: 置換元 × グループの表。正規表現（`$1` などの後方参照つき）、大小区別、適用順（同時／順次）を行ごとに指定
- **表の入出力**: Markdown 表・CSV・TSV からのルール読み込みと、CSV / TSV への書き出し
- **出力**: グループごとの結果を置換箇所ハイライト付きで確認、個別コピー／保存、全ファイルの ZIP 保存
- ライト／ダークテーマ、キーボードだけでのルール表編集

### 「同時」と「順次」

| 適用順 | 動き |
| --- | --- |
| **同時** | 連続する「同時」行をまとめて1回で適用する。そのパスの開始時点のテキストを一度だけ走査し、**長い一致を優先**する（同着ならルールの定義順）。置換で生まれた文字列は同じパス内では再走査しないので、ルールが**連鎖しない**。 |
| **順次** | その行だけを単独のパスとして、**それまでの置換結果の全体に対して**適用する。前のパスの置換結果と周囲の文字列にまたがる一致も拾う。 |

例: `a → b`, `b → c` の2行に `a` を入力すると、両方「同時」なら `b`、2行目が「順次」なら `c` になります。

### 置換先を空にしたとき

置換先が空の行は「削除」ではなく「そのグループでは何もしない」になります。
グループごとに「この語は変えない」を表現するための仕様です。

ただし**正規表現モードなら削除できます**。展開後に空文字になる置換先を書けば、
一致した範囲は取り除かれます（例: 置換元 `(不要な)?文字` ・置換先 `$1` で、
グループが無いときに空になる）。リテラルの置換では削除できません。

### 縦書き用の記法を含む原稿

置換元・置換先は**ただの文字列**として扱います。ルビ記法（`|漢字《かんじ》`）のような
記法も、そのまま書けばそのまま一致します。

ひとつだけ注意が要るのは**取り込む表の書式**です。Markdown 表は `|` を列の区切りとして
使うので、`|` を含むルールを Markdown 表で受け渡すとそこで列が割れます。取り込み側は
`\|` のエスケープを1文字の `|` として読みますが、他のツールが書き出した表はそうとは
限りません。`|` を含むルールを扱うなら **CSV か TSV を使ってください**（このツールの
書き出しもその2つです）。

## 作業データのバックアップ

原稿・グループ・ルールはブラウザの中（localStorage）にだけ保存されます。サーバーには
置かないぶん、**ブラウザ側の都合で消えることがあります**。

- Safari は、サイトへの訪問が7日途切れるとスクリプトが書いた保存領域を消します
- ブラウザの「サイトデータを削除」「履歴を消去」
- プライベートウィンドウを閉じたとき
- 保存領域がいっぱいになったとき（数MB程度で頭打ちになります）

そのため、ヘッダーの**「作業データ」から JSON に書き出して手元に置いてください**。同じ画面から
読み込みもできます。読み込みは「ファイルを選ぶ → 中身を確かめる → 置き換えを確定する」の
3段階で、確定するまで今のデータには触りません。

保存に失敗したときは画面下に警告を出し続けます（消えるトーストにはしていません）。
出ている間の編集は保存されないので、書き出してください。

## 文字コード

- 取り込むファイルは UTF-8 として読み、不正なら **Shift_JIS(Windows-31J)** として読み直します。古い原稿や Excel が書き出した CSV をそのまま渡せます。
- 取り込んだファイルが UTF-8 として読めず Shift_JIS とみなした場合は、その旨を画面で知らせます。**推測でしかない**ので、文字化けが無いか目で確かめてください。書き出しは常に UTF-8 です。
- 正規表現は**常に `u` フラグ付き**で解釈します。`𠮷` のような補助漢字を分断せず、`\p{Script=Han}` も使えます。代わりに `[a-\d]` や裸の `{` のような、`u` が無ければ通る書き方はエラーになります（書き方によって `.` が1文字にも2文字にもなる状態を作らないため）。
- **文字数は表示しません。** 入力の長さに上限を設けていないので、数えても判断材料になりません（サロゲートペアや異体字セレクタをどう数えるかで値が変わるだけです）。長い原稿でも最後まで置換されることは自動テストで担保しています。
- **一致はコードポイント列の完全一致で、Unicode 正規化はしません。** 見た目が同じでも
  合成済みの「が」(U+304C) と「か」+濁点 (U+304B U+3099) は別の文字列として扱われ、片方を
  書いたルールはもう片方に当たりません。macOS から持ってきたファイル名や、入力環境の違う
  原稿を混ぜたときに起きます。当たらないときは、原稿とルールのどちらかを書き直して
  表記を揃えてください（正規化してしまうと、意図して使い分けている表記まで潰すため、
  ツール側では触りません）。

## 対応ブラウザ

スマートフォンでの利用を前提にしており、**Safari も保証対象**です。
自動回帰は Chromium / WebKit（デスクトップ）と WebKit（iPhone エミュレーション）で回しています。
Playwright の WebKit は Safari そのものではないので、リリース前の最終確認は実機で行ってください。
特に**日本語 IME は自動テストで再現できません**（Playwright の入力は OS の IME を通りません）。
ルール表で変換候補を Enter で確定したときに、行移動や行追加が誤発火しないことは実機で見てください。

## 開発

```bash
npm install
npm run dev        # 開発サーバー
npm run check      # lint + typecheck + test + build（コミット前にこれ）
npm run test:e2e   # ブラウザでの E2E テスト（初回は npx playwright install chromium webkit）
```

| コマンド | 内容 |
| --- | --- |
| `npm run dev` | Vite の開発サーバー |
| `npm run build` | 型チェック＋本番ビルド（`dist/`） |
| `npm run preview` | ビルド結果の確認 |
| `npm run lint` | Biome によるチェック（lint + フォーマット） |
| `npm run lint:fix` | Biome の自動修正 |
| `npm run typecheck` | `tsc --noEmit`（アプリ用と Node 側の2構成） |
| `npm run test` | Vitest（ロジックのユニットテスト） |
| `npm run coverage` | Vitest + カバレッジ（閾値つき） |
| `npm run test:e2e` | Playwright（実ブラウザでの E2E テスト） |
| `npm run check` | lint → typecheck → test → build をまとめて実行 |

Node のバージョンは `.nvmrc` と `engines` で 22 に固定しています。

## 構成

```
src/
├── lib/         ロジック（純粋関数・DOM非依存・テストあり）
│   ├── replace.ts    置換エンジン（同時／順次、ヒット数、ハイライト範囲）
│   ├── regex.ts      正規表現のコンパイルと $1 展開
│   ├── table.ts      Markdown 表 / CSV / TSV の入出力
│   ├── zip.ts        依存なしの ZIP 生成
│   ├── fileName.ts   ファイル名のサニタイズと重複解決
│   ├── gridNav.ts    ルール表のキーボード移動
│   ├── format.ts     画面とファイル名の書式
│   ├── text.ts       BOM の付け外し
│   ├── inputFiles.ts 取り込めるファイルの判定と読み込み
│   ├── browser.ts    ダウンロード・クリップボード（唯一の副作用）
│   └── storage.ts    localStorage（読み込み時に検証・正規化）
├── state/       useReducer による状態管理
├── hooks/       React フック
├── components/  UI（ErrorBoundary が復旧画面を持つ）
├── styles/      デザイントークンとコンポーネントCSS
└── types.ts     ドメイン型
e2e/             Playwright の E2E テスト（mobile/ は狭い画面専用）
design/          元になった Claude Design のエクスポート（参照用）
```

### テストの分担

| 層 | ツール | 見るもの |
| --- | --- | --- |
| `src/lib/`, `src/state/` | Vitest | 置換の意味論、表の入出力、ZIP のバイト列、保存データの正規化、reducer の遷移 |
| 画面全体 | Playwright | 変換の流れ、ファイル取り込み、モーダルのフォーカス、キーボード操作、永続化、ダウンロード、狭い画面のレイアウト |

コンポーネント単体のテストは置いていません。UI の振る舞いは E2E で、ロジックはユニットテストで見る、という分け方です。

## デプロイ

Vercel（`vercel.json` 済み）。完全な静的サイトなので、`dist/` をそのまま配信できる
ホスティングであればどこでも動きます。

ソースマップは本番にも出力しています（リポジトリが public なので秘匿するものが無く、
実際に配信されている成果物をそのまま追えるほうが利点が大きいため）。
